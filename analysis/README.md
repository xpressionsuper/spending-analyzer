# 소비 분석 기록

이 폴더는 소비 데이터가 쌓일 때마다 남기는 기록이다. 두 종류가 있다.

| 폴더 | 누가 쓰나 | 내용 |
|---|---|---|
| `data/<데이터 마지막 날>.md` | `node report.js`가 자동으로 | **순수 데이터.** 마지막으로 다 찬 달과 진행 중인 달을 전체 평균·육아 시작 이후 평균·직전 12개월 평균·작년 같은 달과 비교한 표, 카테고리별 차이, 육아 세부, 행동 지표(결제 건수·결제한 날·소액 비율·주말 비중), 월별 표. 해석은 없다. |
| `ai/<분석한 날>.md` | Claude(추론형 AI)가 업데이트 때마다 새로 | **AI 분석.** 최근 달이 잘하고 있는지 못하고 있는지 판단하고, 잘한 점·아쉬운 점·남은 기간 할 일·다음 체크포인트를 쓴다. 이전 파일은 고치지 않고 쌓는다. |

화면(index.html)의 'AI 분석' 탭은 `ai/`의 가장 최근 파일을 보여주고, 날짜를 골라 이전 분석도 볼 수 있다. '순수 데이터' 탭 맨 위의 '최근 달 비교'는 가장 최근 `data/` 기록과 같은 내용이다.

## 업데이트 순서 (Claude Code에서)

1. **데이터 넣기**
   - 쿠팡: `collecting-coupang-orders` 스킬 순서대로 (csv → `to_md.js`로 md)
   - 카카오뱅크: 엑셀 암호 해제 → `python -P bank_to_md.py data/<해제.xlsx>`
2. **계산:** `node build_data.js` → `node report.js`. 새 `data/<데이터 마지막 날>.md`가 생긴다.
3. **AI 분석 쓰기:** 아래 '쓰는 법'대로 `ai/<오늘 날짜>.md`를 새로 만든다.
4. **화면 반영:** `node report.js`를 한 번 더 실행한다 (새 AI 분석이 화면에 들어간다).
5. **공개 전 확인:** 올릴 파일에 상호·실명·지역명이 없는지 확인한다 (build_data.js가 data.public.js는 자동 검사).
6. **올리기:** `git add -A && git commit && git push` → GitHub Pages에 자동 배포.

## AI 분석 쓰는 법

**읽을 것:** 가장 최근 `data/*.md`, 바로 전 `ai/*.md`(특히 '다음 분석 때 확인할 것' 표), 필요하면 이전 `data/*.md`.

**맨 위 머리말:**
```
---
date: 분석한 날 (YYYY-MM-DD)
data_through: 데이터 마지막 날 (data 기록 파일 이름과 같게)
data_record: analysis/data/<데이터 마지막 날>.md
evaluated: 평가한 달 (예: 2026-11 (완료), 2026-12 (10일째까지))
---
```
`data_through`가 실제 데이터보다 오래되면 화면에 'AI 분석 업데이트 필요' 안내가 뜬다.

**권장 구성** (`##`마다 카드 한 장이 된다):
1. `# 제목` — 한 줄 결론 (예: "11월은 기저귀 단가를 잡았지만 주말 지출이 늘었습니다")
2. `## 최근 경향 평가` — 표 `| 항목 | 판정 | 근거 |`. 판정 칸에 `좋아짐` `나빠짐` `주의` `유지` 중 하나를 쓰면 색 칩이 된다. 표 아래에 **종합** 한 문단.
3. `## 지난 체크포인트 결과` — 바로 전 AI 분석의 '다음 분석 때 확인할 것'을 하나씩 달성/미달성으로 평가 (첫 분석에는 없음).
4. `## 잘한 점`, `## 아쉬운 점`
5. `## 이번 달 남은 기간에 할 일`
6. `## 다음 분석 때 확인할 것` — 표 `| 체크포인트 | 목표 | 이번 값 |`
7. `## 기준선` — 전체 그림이 바뀌었을 때만 고쳐 쓴다 (예: 기저귀 졸업, 어린이집 시작)
8. `## 육아 자세히 보기`, `## AI 제안 월 예산`, `## 쿠팡 절감 시나리오`, `## 이 분석의 한계` — 필요할 때

**그래프 넣기:** 한 줄에 `{{chart:이름}}`만 쓰면 계산된 그래프로 바뀐다.

| 이름 | 그래프 |
|---|---|
| `recent` | 마지막으로 다 찬 달의 카테고리별 차이 (이전 평균 대비) |
| `baby-sub` | 육아 세부 항목 (최근 12개월) |
| `baby-half` | 육아 반기별 흐름 |
| `diaper` | 기저귀 장당 가격 |
| `plan` | AI 제안 월 예산 (조정률은 report.js의 `PLAN`) |
| `save` | 쿠팡 절감 시나리오 |

**규칙:**
- 숫자는 `data/` 기록에서 가져온다. 기록에 없는 숫자를 계산했다면 근거를 문장에 밝힌다.
- 공개 저장소에 올라가므로 상호·사람 이름·지역명을 쓰지 않는다 (카테고리, '어린이집', '소아과'처럼 일반 명칭만).
- 현대·KB 카드 대금과 네이버페이 충전은 다루지 않는다 (사용자 요청).
- 이전 `ai/*.md`는 고치지 않는다. 판단이 바뀌면 새 파일에 "지난번과 달리" 식으로 쓴다.
- 월은 월급날 기준 (N월 = 전월 25일 ~ 당월 24일). 진행 중인 달은 같은 일수끼리 비교한 값(`data/` 2절)으로 판단한다.
